# 协议验证记录与架构

验证日期：2026-10-09；初版探测使用 macOS 系统 OpenSSH；0.2.0 已替换为 JavaScript SSH，并在 Bun 1.4、清空 PATH 的环境中验证。

## 0.5.0：Cloudflare 临时远程登录

远程入口参考同作者 `magpie-our-free-model` 的 Quick Tunnel 实现，复用并适配其固定版本下载器和进程监督器。SSH/headless Linux 环境自动选择远程入口，Magpie 同时提供显式 Cloudflare 和本机登录方式；独立登录命令支持 `--cloudflare` 和 `--local`。

临时登录服务仍绑定 `127.0.0.1` 的随机端口。cloudflared 只转发该监听服务；页面只接受本次随机路径、精确 Host 和同源 Origin，不提供模型 API 或凭证接口。公开页面只含公钥和指纹，浏览器不接触私钥。隧道不改变到 HF 的 SSH 连接路径，也不能修复服务器无法访问 `chat.hf.co:22` 的问题。

优先检查已有客户端；缺少时下载官方 cloudflared 2026.10.0，校验固定大小及 SHA-256，macOS 额外校验解压后的可执行文件。支持 Linux/macOS x64、arm64 及 Windows x64，二进制不随包分发。保留原 Apache-2.0 许可及来源说明。客户端下载使用临时目录和原子发布，校验失败不会执行；有效缓存可以离线复用。

每次通道使用独立空配置，并移除 `TUNNEL_*` / `CLOUDFLARED_*` 环境变量，避免已有具名隧道设置改变目标。使用 HTTP/2、IPv4 和回环 metrics 端口，不安装系统服务。启动有独立 45 秒超时，完整登录默认十分钟；结束登录时停止进程并删除临时配置，运行缓存保留以供下次登录。监督器在宿主进程被强制终止或 stdin 关闭后也会停止 cloudflared。

2026-10-10 验证：Node/Bun 离线回归覆盖下载完整性、缓存污染、官方重定向限制、macOS 归档、Host/Origin 和路径限制、启动失败、下载取消、登录取消、超时及宿主强制退出后的进程清理。真实下载并启动官方 macOS arm64 客户端，建立 Quick Tunnel；外部 HTTPS 公钥页返回 200，公钥逐字匹配且不含私钥，模型 API 路径返回 404，结束后进程和临时配置关闭清理。本机系统 DNS 首次持续返回 ENOTFOUND，后续通过 Cloudflare 公共 DNS 解析及保留主机名 TLS 校验的 HTTPS 请求完成验证，因此不能将隧道已连接视为每个浏览器的 DNS 已生效。该验证未代替用户在 HF 添加公钥后的完整登录。

## 0.4.0：公钥链接认证与额度错误

2026-10-09 后续复测中，真实 HTTP SSE、AI SDK Agent 和官方 Magpie 插件宿主均未能完成对话，旧实现返回 `ssh_response_timeout`。直接检查 SSH 终端发现，上游已显示 `Your SSH key is not linked to a Hugging Face account, log in below to chat with it.`、设备授权地址及 `waiting for you to approve`，不再显示此前的匿名聊天欢迎页。

登录页底部仍有 `Ask anything` 输入框，旧实现错误地将其判断为可聊天，发送提示后持续等待回复。现在先识别登录要求，直接返回 `403 hf_login_required`（SSE 中为同名错误事件），关闭连接并释放队列，不发送提示或自动重试。此次复测不能确定登录要求是全局政策变化还是当前连接环境限制。

认证先尝试 SSH 原生设备码授权：用户确认后当前会话登录成功，但相同密钥重新连接仍要求登录。最终改用 HF 官方 SSH Keys 页面，由用户添加插件生成的专用公钥。两次全新 SSH 连接均识别到同一 HF 账号，确认关联可以跨连接复用。

Magpie 提供浏览器链接认证方法，验证后由宿主保存私钥；独立服务使用 `scripts/login.mjs`，将凭证原子写入 `.local/ssh/auth.json`，文件权限为 `0600`。每次请求读取当前账号凭证；私钥不作为 HTTP API Key 返回。旧版自动注册的 `anonymous` 配置需要重新登录。

登录链接先打开临时本地页面，提供「复制公钥」按钮及可全选的只读文本框，再链接到 HF 官方 SSH Keys 页面。页面仅绑定 `127.0.0.1` 的随机端口和随机路径，只包含公钥及指纹；认证成功、失败、取消或超时后关闭。浏览器剪贴板不可用时尝试兼容复制，再退回全选手动复制。远程运行保留登录说明中的完整公钥及 HF 链接。

2026-10-10 排查添加公钥后登录失败的问题：现场已有凭证能识别账号，未关联密钥进入登录等待，尚未复现用户的具体失败。代码确认此前自动验证仅重试 `hf_login_required`，一次临时断连、握手超时或第二次验证连接失败就会提前结束登录。现将暂时网络错误及 SSH 认证尚未通过纳入轮询，保留本次登录密钥；最终超时附带最近检测原因。主机指纹变化及本地文件权限错误仍立即失败。离线回归覆盖关联前、第二次验证中的断连及超时，确认成功仍需要两次全新连接识别同一账号。

登录后的真实聊天返回 `402 Payment Required`，提示账号没有剩余 Inference Providers credits。插件已从助手回复区域识别上游错误，非流式请求返回 HTTP 402 和 `hf_insufficient_credits`，SSE 返回同名错误事件及 `[DONE]`；错误前不会输出助手回复。已验证两种路径不再等待到 `ssh_response_timeout`，官方 Magpie Bun 宿主也验证了凭证加载及该错误的传递。登录后成功回复及完整工具循环仍受账号额度阻塞，尚未验证。

## 实现路径

1. Magpie/OpenCode 的 Provider `loader.fetch` 或独立 HTTP 服务接收 Chat Completions。
2. 校验请求；把消息历史、工具结果、JSON Schema 与工具选择序列化进提示词。
3. 从 Magpie 当前账号或独立服务凭证文件读取已关联的 ECDSA 私钥。`ssh2` 在 Bun 内为每个请求建立独立 SSH 连接，申请远端 PTY，无外部命令或系统 PTY。首次信任并保存主机指纹，后续拒绝变化。
4. `@xterm/headless` 重建屏幕与应答能力查询，处理光标移动、局部重绘和拆分的 UTF-8/ANSI。
5. 从模型回复区域读取带随机分隔符的 JSON，要求结束标记、空闲输入框与稳定屏幕；不以单纯静默判定成功。稳定的上游错误直接转换为余额不足、登录要求、限流或通用错误。
6. 校验函数名、参数 schema、工具选择和并行开关，再生成标准 Chat Completions / SSE。
7. 客户端执行工具后，在下个请求中携带完整历史与 `tool_call_id`；插件不执行工具。

## 0.3.0 匿名可靠性优化

- 复现：240 列终端下，包含多行代码的工具参数会被 HF Markdown 排版主动折行，导致 JSON 非法。Markdown 转义也可能改变引号和反斜杠。
- 调整：申请 8192 列、64 行虚拟终端，要求模型将完整 envelope 放入纯文本代码块，JSON 对象保持单行。4000 字符的 JSON 上限同时用于提示和解析校验，超出时返回 `reply_too_large`，不会裁剪参数。
- 读取终端自动折行时按 `isWrapped` 还原逻辑行，保留真实空格，去除中文宽字符在行尾产生的空白占位。
- 真实 AI SDK `ToolLoopAgent` 的 SSE 三轮流程通过：读取临时文件、精确复制到另一个临时文件、返回 `COPY_OK`。包含中文、缩进、引号、反斜杠、Markdown 特殊字符的 663 字符内容逐字一致。该测试仅操作自己创建的临时目录，不接触用户项目文件。
- 默认最多保留 8 个请求，包含当前执行项。过载时在打开 SSE 前返回 HTTP 503；取消等待项不执行，超时后释放队列。JSON/SSE 共用错误结构。
- 长历史探测发现输入框会截断超长粘贴；8000 字符的尾部完整，8001 字符丢失最后一个字符；7000 个中文字符的尾部完整，限制不是 UTF-8 字节数。输入上限改为 8000 字符，包含协议指令和工具定义（本地按 UTF-16 长度保守计数）。超限在连接前返回 `context_length_exceeded`，避免模型只读到历史开头而遗漏最新要求。此前的 60000 字符本地上限不能保证完整传入上游。
- 6428 字符的真实历史请求正确复述开头的 `EARLY_CONTEXT_9286` 和最后一条消息的 `LATEST_CONTEXT_3175`，耗时约 40 秒。
- 工具 Schema 编译后释放全局缓存引用，避免多轮请求累积 Schema 或重复 `$id` 导致误报。
- 仅在发送提示词之前，针对暂时网络故障重连一次。开始粘贴后、主机指纹不符、模型格式失败时不自动重试。
- 模型目录刷新失败后保留缓存，30 秒内避免反复访问失败的上游。目录单独标注 SSH 计费状态，不从 HTTP 供应商报价推断 SSH 费用。

HF 模型的思考时间计入请求超时。一次历史匿名流程通过不代表任意长文件或所有 Agent 均稳定；完整 Magpie 网关、Windows 实机及登录后完整工具循环仍未验证。

Magpie 安装插件时负责准备 Bun 与 npm 依赖，其宿主不运行依赖安装脚本。`ssh2` 的原生加速为可选项；本插件在禁用安装脚本、没有原生加速的环境中运行。0.2.0 / 0.3.0 曾自动登记匿名账号；0.4.0 不再自动登记账号，凭证由浏览器认证回调交给宿主保存，并通过宿主提供的 `getAuth` 读取。

测试发现 `ssh2` 1.17 的 Ed25519 key generator 会错误剥除公钥的有效零前缀，偶尔生成无法解析的密钥。0.2.0 使用 ECDSA P-256 避开该路径。

未验证的能力不会从上游 HTTP 模型目录自动继承。目录保留所有模型，额外说明 SSH 访问情况；活动路由池仅启用当前实现支持的默认模型，其他模型返回 `model_not_supported`，不会暗示登录后即可切换。

## 接下来值得讨论

- 使用有可用额度的账号验证登录后的真实回复和完整工具循环。
- 登录后 `/model` 的完整菜单与公开目录是否一致，模型切换与 provider 后缀是否受支持。
- 真实 Agent 长上下文、长参数、文件编辑时的终端截断和 JSON 换行问题。
- 是否存在 HF 官方稳定结构化协议；若有，应优先替换终端模拟层。
- 使用完整 Magpie 应用 / 网关验证协议转换、模型刷新、取消和真实 Agent 工具执行循环。
